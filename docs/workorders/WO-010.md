# WO-010 同步协作与圆桌治理

## 背景

最新来源仓库已细化 native visible child、独立 worker、fallback、自动归档、圆桌双轮评审和关键治理文档前置评审。`repo-governance v0.2.1` 的 worker 协议仍停留在“真实独立会话”和“可见 worker”层面，未区分执行体类型，也没有圆桌和关键文档评审协议。

## 根因

此前抽取协作方法时，最新执行体治理和关键文档评审规则尚未沉淀完成；同时项目级规范与 v5.0-src 对 WO 执行 worker 可见性的口径不同，通用 Skill 不能固定单一模式，而应目标仓库优先并保守默认。

## 实施要求

1. WO / 开发子任务执行体按目标仓库显式政策选择；无政策时主会话串行。
2. 区分 invisible executor、native visible child、independent worker 和 fallback worker。
3. 独立 worker 不得登记为 native child。
4. 只有真实 child 启动失败才允许一次性 fallback；主会话下发错误不算失败。
5. 执行结束必须记录关闭、归档或逻辑收口证据。
6. 圆桌必须 Round 1 独立评审、Round 2 交叉互评；输出保留原始文件。
7. 圆桌结束后必须归档全部可见分析子智能体或 worker；失败登记待确认。
8. 关键治理文档修改前必须完成前置评审并记录确认来源。
9. 不硬编码模型名、工具实现或来源项目路径。
