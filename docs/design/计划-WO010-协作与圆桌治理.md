# WO-010 实施计划：协作与圆桌治理

## 目标

同步最新仓库中的执行体治理、自动圆桌讨论和关键治理文档前置评审方法，同时保持 `repo-governance` 的目标仓库优先原则：不把某种 worker 可见性策略硬套到所有仓库。

## 已核实差异

1. 当前 `worker-protocol.md` 只要求真实独立会话，并保留“优先可见 worker”的旧表述。
2. 最新仓库要求区分 native visible child、独立 worker、fallback worker，并记录启动方法、父子关系、执行者、状态、关闭或归档证据。
3. 最新仓库要求自动圆桌讨论包含 Round 1 独立评审和 Round 2 交叉互评，结束后归档可见分析会话。
4. 最新仓库要求修改关键治理文档前先做关键文档变更评审。
5. 项目级规范与 v5.0-src 对 WO 执行 worker 可见性存在不同口径；因此通用 Skill 必须目标仓库优先，而不是固定一种模式。

## 设计要点

1. 新增 `references/collaboration-governance.md`：
   - 主会话串行为无约束默认。
   - WO / 开发子任务执行体按目标仓库显式政策选择。
   - 区分 invisible executor、native visible child、independent worker 和 fallback worker。
   - 禁止把 `thread/start` 独立 worker 登记为 native child。
   - 只有真实 child 启动失败才允许一次性 fallback。
   - 执行结束必须记录关闭、归档或逻辑收口证据。
   - 禁止 shell 后台进程、普通命令输出或主持人自答冒充模型执行体。
2. 新增 `references/roundtable-protocol.md`：
   - 触发条件、双模型独立评审、交叉互评、必要追加轮次。
   - 只读分析、原始输出留痕、结论和分歧沉淀。
   - 结束或终止后归档全部可见分析子智能体或 worker。
   - 归档失败登记待确认，不得伪造。
3. 更新 `worker-protocol.md`：
   - 默认主会话串行。
   - 启动前读取目标仓库执行体政策。
   - 增加执行体身份、启动、状态和收口留痕。
4. 更新诊断与初始化：
   - 已有仓库识别目标执行体政策、圆桌规则和关键文档评审规则。
   - 无约束仓库默认不启动 worker 和圆桌。
5. 更新模板：
   - `AGENTS.template.md` 增加执行体政策、圆桌政策和关键治理文档评审。
   - `WO.template.md` 增加关键治理文档评审记录。
6. 保留 explicit-only 调用策略。
7. 版本升级为 `0.3.0`。

## 文件职责

1. `references/collaboration-governance.md`：执行体选择、证据、降级、收口和防伪规则。
2. `references/roundtable-protocol.md`：圆桌触发、轮次、留痕、归档和 fail-closed 规则。
3. `references/worker-protocol.md`：接入执行体治理并保留 WO 分发边界。
4. `references/diagnose.md`：识别既有协作、圆桌和关键文档评审规则。
5. `references/bootstrap.md`：无约束仓库采用保守默认。
6. `assets/templates/AGENTS.template.md`：目标仓库最小协作治理模板。
7. `assets/templates/WO.template.md`：关键治理文档评审记录。
8. `tests/test_collaboration_governance.py`：锁定目标仓库优先、防伪、归档、圆桌和关键评审契约。
9. `SKILL.md`、`README.md`、`VERSION`：入口、状态和版本更新。

## 不做什么

1. 不硬编码某两个模型名；模型随目标仓库配置或用户显式指定。
2. 不规定所有仓库的 WO worker 可见性；目标仓库显式规则优先。
3. 不启动 worker、圆桌或自动归档。
4. 不实现 app-server JSON-RPC 脚本。
5. 不修改来源仓库。
