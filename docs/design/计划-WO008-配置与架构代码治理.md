# WO-008 实施计划：配置与架构代码治理

## 目标

把来源项目中已验证的配置集中、架构分层、依赖方向、巨石代码 ratchet 和兼容层治理方法泛化为 `repo-governance` 的 L1 代码治理能力，防止新仓库继续沉淀配置散落和巨石代码。

## 设计要点

1. 新增 `references/code-governance.md`，作为配置治理与代码结构治理事实源。
2. 配置治理不预设具体文件名或框架，要求按类别确定唯一事实源、提交 example、隔离运行时配置和 secrets、定义优先级和安全默认值。
3. 架构治理要求说明入口层、应用层、领域层、基础设施/适配层的职责和单向依赖。
4. 巨石治理先识别和登记基线，再使用单入口与聚合双层 ratchet；默认禁止已识别巨石继续增长。
5. 新行为优先进入边界清晰模块；巨石内只允许薄 adapter、委托或净删除。
6. 兼容 shim、影子实现、动态 import 别名必须带删除条件和承接位置。
7. 工单模板增加 `架构影响` 与 `配置影响`。
8. 不预设语言通用行数阈值；优先使用目标仓库 lint/type/architecture/import 工具和定制基线。

## 文件职责

1. `references/code-governance.md`：配置治理、分层边界、依赖方向、巨石识别、ratchet、迁移和工单影响。
2. `references/diagnose.md`：能力矩阵加入配置、架构、依赖、巨石和兼容层。
3. `references/bootstrap.md`：L1 初始化加入最小代码治理检查。
4. `assets/templates/AGENTS.template.md`：落目标仓库的配置与架构硬约束。
5. `assets/templates/WO.template.md` 与 worker prompt 模板：新增架构影响、配置影响和 worker 执行边界。
6. `references/worker-protocol.md`：要求主会话向 worker 显式传递架构与配置边界。
7. `tests/test_code_governance.py`：验证配置、分层、巨石、兼容层、工单影响和去来源项目化。
8. `SKILL.md`：增加代码治理入口路由。
9. `README.md` 与 `VERSION`：更新当前能力和版本。

## 不做什么

1. 不实现通用复杂度扫描器。
2. 不预设跨语言统一行数阈值。
3. 不自动启动巨石 ratchet 门禁。
4. 不修改任何目标仓库或来源仓库。
