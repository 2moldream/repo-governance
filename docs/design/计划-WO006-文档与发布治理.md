# WO-006 实施计划：文档与发布治理

## 目标

沉淀 L4 文档事实源、生命周期、目标/现状分离、工单影响声明和发布证据链的适配协议。L4 默认关闭，只作为长期仓库的可选增强，不自动生成 Heavy 治理资产。

## 设计要点

1. L4 默认关闭；启用需用户确认。
2. 先诊断既有文档和发布流程，不直接迁移目录。
3. 一个事实一个主事实源；目标设计不得伪装当前行为。
4. 文档生命周期固定为 `draft / active / superseded / historical`。
5. 工单必须回答文档影响、事实源变化和待办变化；无影响也要写理由。
6. code-map、document map、自动门禁和 release manifest 均为可选增强。
7. 文档检查不能替代测试、安全、E2E 或业务验收。

## 文件职责

1. `references/document-governance.md`：L4 启用条件、最小基线、事实源矩阵、生命周期、工单影响、可选增强和发布证据。
2. `tests/test_document_governance.py`：验证默认关闭、关键不变量和边界。
3. `SKILL.md`：增加 L4 显式入口。
4. `README.md`：更新当前阶段。

## 不做什么

1. 不实现 code map 生成器。
2. 不实现文档门禁脚本。
3. 不移动或改写目标仓库历史文档。
4. 不创建 release manifest。
