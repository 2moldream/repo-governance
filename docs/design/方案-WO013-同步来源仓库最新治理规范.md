## 设计决策

1. **分层归属**：声明级义务进 L1 默认（acceptance_tier 字段、详设影响声明、证据目录边界、并行义务）；工具级自动化（design-delta 台账工具、接口地图 stale 检查、ratchet）保持默认不启动，与 WO-008 配置/架构治理的分层先例一致。
2. **执行体中立**：Claude 执行体作为 collaboration-governance 的新执行体模式（与 Codex 各模式并列），不是新分层；目标仓库政策优先的原则不变。
3. **通用化红线**：不写死来源仓库的工具路径、模型名、数据集路径；引用示例一律用通用表述（"宿主平台子代理工具"而非具体产品名）。
4. **命名消歧**：验收等级 L0/L1/L2 与治理能力分层 L1-L4 同名不同义，文档中必须显式区分（"验收等级" vs "能力分层"）。
