# 已有约束诊断

目标仓库已有显式开发约束时使用本参考。用户确认具体合并方案前，只执行只读诊断；不得直接写入，不得直接覆盖、重排或删除仓库治理文件。

## 1. 盘点输入

只读取理解治理所需的内容：

1. 代理与贡献规范：`AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、`CONTRIBUTING.md`、`README.md`。
2. 流程模板：Issue 模板、PR 模板、维护指南、运行手册。
3. 自动化策略：CI workflow、pre-commit hook、必需检查、发布任务。
4. 命令：测试、lint、类型检查、格式化、构建、打包和部署命令。
5. 配置治理：配置框架、example/config 边界、secret 管理方式、优先级、默认值和校验工具。
6. 代码结构：入口清单、模块职责、分层模型、依赖方向、import/architecture 检查、循环依赖和外部调用边界。
7. 屎山风险：大入口、多职责文件或函数、影子副本、兼容 shim、动态加载和缺失删除条件。
8. 协作执行体政策：WO / 开发子任务、native visible child、invisible executor、independent worker、fallback、关闭和归档要求。
9. 圆桌政策：触发条件、参与模型、轮次、原始输出、归档和 fail-closed 规则。
10. 关键治理文档评审：哪些文档属于关键文档、评审提交、确认来源和回退要求。
11. 仓库拓扑：默认分支、集成分支、活跃分支、标签、submodule/worktree 使用情况和脏状态。
12. 工作跟踪：本地工单、GitHub Issues、Jira、TAPD 或其他外部系统。
13. 归属与合并政策：谁可以合并、是否允许直推、评审要求。

不得搜索无关用户目录、secrets、依赖缓存、构建产物或大型历史归档；不得输出凭据或含密配置。

## 2. 分类

每个相关内置能力必须归入且只归入一类：

| 类别 | 含义 | 处理 |
|---|---|---|
| 一致 | 仓库已有等价规则 | 保留仓库原文，不重复写入 |
| 重复 | 双方以不同表达提出同一要求 | 保留更精确的一方并链接 |
| 缺失 | 仓库缺少基线能力 | 提议最小补充 |
| 冲突 | 双方规则不能同时执行 | 除安全底线外保留仓库规则，并给出显式调和建议 |
| 仓库专属例外 | 仓库因领域、历史、工具或团队原因有意偏离 | 保留并记录例外 |

需比较的内置能力：

1. 先方案后开发。
2. 缺陷先根因后修复。
3. 工单或任务身份。
4. 分支命名和基线分支。
5. 范围与范围外处理。
6. 行为变化声明。
7. 验收命令与结果记录。
8. 开放事项台账。
9. 配置唯一事实源、优先级、example/config 边界和安全默认值。
10. 架构分层、依赖方向和外部调用边界。
11. 屎山识别、ratchet 和切片迁移。
12. 兼容层、影子实现和动态加载删除条件。
13. 多 worker 分发。
14. 执行体身份、启动证据、一次性 fallback 和收口留痕。
15. 圆桌触发、双轮评审、结论沉淀和自动归档。
16. 关键治理文档变更前置评审。
17. 多 worktree 隔离。
18. 长期集成分支与合并治理。
19. 文档事实源与发布证据。

## 3. 证据契约

每个对照行必须包含：

```text
能力：
仓库规则原文：
仓库规则位置：
内置规则摘要：
分类：
影响：
合并建议：
```

要求：

1. 只引用相关句子或条目，能短则短。
2. 尽量使用稳定文件路径和行号。
3. 区分观察到的事实和推断。
4. 说明对范围、分支、自动化、评审或验收的影响。
5. 冲突不得隐藏任何一方，也不得静默裁决。

## 4. 冲突裁决

默认优先级：

1. 目标仓库显式规则优先。
2. 已记录且适用的仓库专属例外优先。
3. 内置方法论只补缺口。

以下安全底线优先于仓库偏好，必须停止并询问：

1. 未授权或范围外变更。
2. 无证据声称成功。
3. 缺证据按通过处理。
4. 绕过必需安全或安保检查。
5. 暴露 secrets 或凭据。
6. 破坏性 Git 操作。
7. 将后台进程或主持人自答伪装成独立 worker。

## 5. 诊断报告

写入前输出：

```markdown
# 仓库治理诊断

## 结论

<仅诊断 / 可初始化 / 冲突需决策>

## 仓库盘点

<约束、命令、分支、工单系统、合并政策>

## 能力矩阵

| 能力 | 分类 | 仓库规则位置 | 影响 | 建议 |
|---|---|---|---|---|

## 冲突与例外

<带证据的对照行；无则写“无”>

## 建议合并方案

<精确到文件和章节；尽量保留现有表述>

## 不修改文件

<路径与原因>

## 验证方案

<既有检查与建议检查>

## 待确认问题

<需要用户决策的问题；无则写“无”>
```

输出报告后结束本轮并等待用户确认。
