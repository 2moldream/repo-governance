# 文档与发布治理协议

L4 默认关闭。只有长期演进、多人/多 worker 并行、文档漂移造成误读或返工、发布需要可追溯证据时，才建议启用；启用前必须获得用户确认。

## 1. 启用诊断

先只读盘点：

1. 文档入口和阅读顺序。
2. 当前架构/代码导航。
3. 设计、方案、决议、排查和工单分区。
4. 发布记录、manifest、回滚说明。
5. CI 对文档、链接、schema 或产物的检查。
6. 历史文档是否已标注替代关系。

输出与 `diagnose.md` 相同的能力矩阵；不得为了 L4 直接移动、合并或删除历史文档。

## 2. 最小落点

启用 L4 的最小文件：

1. `docs/README.md`：文档入口和事实源矩阵。
2. 工单模板：增加文档影响声明。
3. 开放事项登记：记录文档漂移和未完成整理。

不默认创建 code map、document index、release gate 或自动脚本。

## 3. 事实源矩阵

按问题域裁决，不使用全局线性优先级：

| 问题域 | 首要事实源 | 漂移处理 |
|---|---|---|
| 当前实现行为 | 指定 commit 的代码、测试、可追溯产物 | 修正文档或登记偏差 |
| 开发约束 | AGENTS / 贡献规范 / 适用流程文档 | 代码违规不改变约束效力 |
| 目标设计 | 已确认设计文档 | 目标不得证明已落地 |
| 业务或产品口径 | 业务/产品决议台账 | 实现不足不改变口径 |
| 当前代码定位 | code map 或实际代码索引 | 与代码不一致时修地图 |
| 开放事项 | 全局待办登记 | 待办不是规则或架构事实 |
| 发布行为 | release record、tag、manifest、不可变产物 | 只对对应版本权威 |
| 历史解释 | 历史方案、旧工单、诊断 | 只追溯，不参与当前裁决 |

跨域冲突必须写：

```text
事实：<代码或产物观察到什么>
约束：<规范或决议要求什么>
偏差：<登记到哪个工单或待办>
```

## 4. 生命周期

```text
draft -> active -> superseded -> historical
```

1. `draft` 不作为裁决依据。
2. `active` 是当前有效事实源。
3. `superseded` 必须指向替代对象。
4. `historical` 只解释过去，不改写成当前现状。
5. `generated` 是来源属性，不是生命周期。

## 5. 工单影响

每张 WO 至少回答：

```text
文档影响：有 / 无（无影响写理由）
事实源变化：有 / 无（无影响写理由）
待办变化：有 / 无（无影响写理由）
```

触及入口、模块边界、接口、状态机、数据产物、配置、部署、发布路径或业务口径时，不得声明无文档影响。

## 6. 可选增强

按需单独立项：

1. document map：文档类型、责任和生命周期。
2. code map：当前代码入口和职责，JSON 为可编辑源，Markdown 为生成视图。
3. 链接和路径校验。
4. 工单文档影响门禁。
5. release manifest 与发布证据链。
6. repository governance report。

每项启用前说明成本、维护责任、检查频率和失败处理。不得一次启用全部 Heavy 资产。

## 7. 发布证据

发布记录至少绑定：

1. source commit。
2. tag 或包版本。
3. 验收命令和结果。
4. 产物 checksum。
5. 运行环境或部署目标。
6. 回滚方式。
7. 已知问题与开放事项。

目标设计、未合入分支和草稿文档不能作为发布事实。文档检查通过不等于测试、安全、E2E、运维验证或业务验收通过。
