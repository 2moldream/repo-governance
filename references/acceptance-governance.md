# 分级验收治理

验收等级决定一张 WO 必须提供哪些验证证据，不决定能力是否启用。目标仓库已有更严格的验收要求时，执行更严格者；不得以本协议替代仓库的强制检查。

## 1. 命名与声明

每张 WO 必须在实施前显式声明 `验收等级：L0 / L1 / L2`，验收后记录实际执行的等级、命令和结果。

**验收等级 L0/L1/L2 与能力分层 L1-L4 同名不同义。** 前者描述单张工单的验证深度，后者描述仓库启用的治理能力；能力分层为 L1 不意味着工单验收等级只能是 L1，验收等级也不能用于启用或关闭能力分层。

默认验收等级为 L1。未声明等级时按 L1 执行，但不得补填声明来代替实际验收。

## 2. 等级定义

| 验收等级 | 适用边界 | 最低证据 |
|---|---|---|
| L0：零行为变化 | 不改变运行行为的纯文档、格式或说明性改动 | 相关专项检查，或逐项说明无需专项检查的理由；生成视图一致性检查；文档链接、事实源与治理一致性检查；`git diff --check` 及范围检查 |
| L1：默认行为变化 | 一般代码、模板、配置或 Skill 行为变化，以及无法证明零行为变化的改动 | 全部 L0 证据；全量测试；既有快照零漂移，或另行评审并显式批准的快照变更；相关回归测试；仓库 fast gate |
| L2：关键路径 | 发布、合并、迁移、安全、生产恢复或其他高影响关键路径 | 全部 L1 证据；代表性数据集或 live E2E；双模型完整圆桌；仓库 full gate；可复核的发布证据 |

等级是最低要求，不是可勾选的完成状态。目标仓库未定义 fast gate、full gate、生成视图或代表性数据集时，必须在方案与工单中定义可执行替代项和输出位置；未定义即缺证据，fail-closed。

## 3. 升级与误判约束

1. L0 检查、代码审查或用户反馈发现任何行为漂移时，立即停止按 L0 收口，自动升级为 L1；若漂移触及关键路径，则升级为 L2。
2. 升级后必须补齐新等级的全部证据，并记录触发漂移、升级前后等级和新增命令；不得删除原失败记录。
3. 同一工单累计发生两次验收等级误判后，该工单至少以 L1 起报；后续不得再以“原本只改文档”或类似理由降回 L0。
4. 验收范围扩大、关键路径风险显现或证据链变化时，应主动重估等级。
5. 降级只允许发生在实施前，且必须有新的范围证据；验收失败后不得通过降级绕过检查。

## 4. 验收证据与禁止事项

每张工单至少记录：

```text
验收等级：
等级理由：
实际验收等级：
升级记录：
专项检查：
全量测试：
回归测试：
fast/full gate：
快照或生成视图结果：
代表集/live E2E：
圆桌结论引用：
发布证据引用：
```

1. 禁止只修改验收等级字段、声明或状态来冒充已完成验收；字段变化不是证据。
2. 禁止只运行便于通过的子集，再声称满足全量测试或 gate 要求。
3. 快照漂移必须显式审查；未获批准的漂移不能写成“零漂移”。
4. 代表集、live E2E、圆桌和发布证据必须可追溯，不能只写“已检查”。
5. 缺命令、缺输出、缺材料或结果失败时，工单保持开放并登记原因；不得声称完成。
